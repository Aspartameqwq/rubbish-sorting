# K230—STM32 四框分拣通信协议与 STM32 状态机

## 1. 范围和当前标定状态

本文记录 STM32 固件提供的 HC-04 通讯、动作状态机和联调约定。当前仓库只修改 STM32；K230 的接收与重新识别流程是双方协议约定，不在本次工程修改范围内。

当前工程没有 Yaw 或 Pitch 位置传感器。Yaw 到位使用步进电机已输出脉冲换算出的开环命令位置；Pitch 到位使用舵机命令角与非阻塞时间轨迹。软件到位不等于实机位置测量。

四框动作在完成实机测量前保持禁用。`Config/project_config.h` 中 `SORT_MECHANICAL_CALIBRATION_COMPLETE` 默认是 `0U`，四个 Pitch 方向默认是 `0`，倾倒角和两个 Yaw 分组角默认是 `0L` 占位值。标定完成前，STM32 对有效 `S` 命令回复 `N,id,FAULT`，且不发送 `R`。

## 2. UART 帧格式

USART1 经 HC-04 通讯，配置为 `115200`、8N1、无流控。HC-04 驱动检查 CubeMX 生成的 UART 波特率是否与 `HC04_BAUDRATE` 一致，不会在运行时改写 UART 配置。

分拣帧格式为：

```text
$内容*CC\n
```

`CC` 是两位十六进制 CRC-8/ATM。参数为多项式 `0x07`、初值 `0x00`、非反射输入/输出、异或输出 `0x00`；CRC 仅计算内容 ASCII 字节，不包含 `$`、`*`、CRC 字符或 LF。分拣帧要求 LF 结束，不接受 CR。

协议回归帧：

```text
$S,42,3*6C\n
```

其内容为 `S,42,3`，CRC 为 `0x6C`。有效出站响应也使用同一帧格式。

| 方向 | 内容 | 含义 |
|---|---|---|
| K230 → STM32 | `S,action_id,box` | 请求分拣；box 只能为 1–4 |
| STM32 → K230 | `A,action_id` | 已接受，动作尚未完成 |
| STM32 → K230 | `D,action_id,0` | 动作成功，Pitch 已回正且 Yaw 已回 HOME |
| STM32 → K230 | `D,action_id,1` | 已接受的动作执行失败，STM32 进入故障状态 |
| STM32 → K230 | `N,action_id,BUSY` | 正在处理其他动作 |
| STM32 → K230 | `N,action_id,FAULT` | 现有故障、未标定或不满足安全 READY 条件 |
| STM32 → K230 | `N,action_id,BAD_BOX` | box 不在 1–4 范围内 |
| STM32 → K230 | `N,action_id,ID_CONFLICT` | 保留的 action_id 已对应另一个 box |
| STM32 → K230 | `R` | 空闲且安全，可以接收下一件物品 |

`action_id` 为十进制 `uint32_t`（0–4294967295）；box 是十进制整数。CRC 或帧格式错误的分拣帧会被计数并丢弃，不执行动作。

每个分拣响应单独成帧，例如 `$A,42*CC\n`。原有纯文本调试协议继续可用；分拣帧和纯文本命令由同一主循环解析。完整旧命令语法见 [protocol.md](protocol.md)。

## 3. 接收与主循环

USART1 RX 使用 DMA1 Channel 5 循环缓冲区（256 字节）和 `HAL_UARTEx_ReceiveToIdle_DMA()`。UART DMA 回调只更新半缓冲区/满缓冲区事件计数；UART 错误回调只记录错误标志。中断回调不解析命令，也不驱动电机或舵机。

主循环先调用 `HC04_Process()` 更新 DMA 生产位置，再由 `Protocol_Process()` 逐字节取数、寻找 LF、校验 `$`、`*`、长度、CRC 并解析字段。每轮协议任务最多处理 `PROTOCOL_MAX_BYTES_PER_PROCESS`（默认 64）个字节；缓冲区溢出或 UART 错误后丢弃残帧并等待 LF 重新同步。

接受新动作的处理顺序是：box 合法性 → action_id 历史查询 → 故障检查 → BUSY 检查 → READY/配置/目标检查 → 预留任务和历史记录 → 发送 `A` → 进入 `YAW_MOVE`。状态机之后在主循环推进，不在通信回调中动作。

## 4. action_id 去重和冲突

固件用 `SORT_ACTION_HISTORY_CAPACITY` 项环形 RAM 表记录 action_id、box、结果及完成标志，默认 8 项，允许配置为 4–8 项。新动作在发送 ACK 之前预留记录；完成或失败时写入最终结果。

- 历史中相同 ID、相同 box 且未完成：只重发 `A`，不重启动作、不改状态进入时间。
- 相同 ID、相同 box 且已完成：重发缓存的 `D,id,result`，不重复动作。
- 相同 ID、不同 box：增加 `protocol_id_conflict_count`，回复 `N,id,ID_CONFLICT`，不更改任务或历史记录。
- 全新 ID 在执行期间到达：回复 `N,id,BUSY`，不排队。
- box 非法优先回复 `N,id,BAD_BOX`。
- 新动作接收前已故障或标定/READY 条件不满足：回复 `N,id,FAULT`。

历史仅保存在 RAM，复位后清空；环形表写满后只保留最近 8 项。因此 K230 应使用不重复的 action_id，并将动作结果超时后的同 ID 重发限制在 STM32 的当前历史窗口内。此机制不提供跨复位的持久去重。

收到 `N,id,ID_CONFLICT` 后，K230 应废弃冲突命令，不得修改 box 后沿用原 ID。若 STM32 正忙，等待后续 `R`；满足合法取料和识别条件后重新识别，并为新请求分配一个新 action_id。K230 的这段逻辑仅作为协议约定，本次未修改 K230 工程。

## 5. 分拣状态机

正常状态顺序如下：

```text
IDLE
  → YAW_MOVE → YAW_WAIT
  → PITCH_DUMP → PITCH_DUMP_WAIT
  → DUMP_HOLD
  → PITCH_RETURN → PITCH_RETURN_WAIT
  → YAW_RETURN → YAW_RETURN_WAIT
  → COMPLETE → IDLE
```

每个 `MOVE` 状态只提交一次目标，然后转入对应 `WAIT`。等待态检查轴到位并检查超时；超时、非法目标或轴/驱动错误会进入锁存 `FAULT`，停止正在运行的 Yaw，并对已经 ACK 的动作发送 `D,id,1`。动作接受前的拒绝使用 `N`，接受后的执行失败使用 `D`。

`DUMP_HOLD` 用系统 Tick 做无符号差值比较，默认保持 `1000 ms`。Pitch 回正等待成功之前不会设置 Yaw 回零目标；只有 Pitch 位于 HOME、Yaw 位于 HOME 且无故障时才发送成功 `D`。故障态不发送 `R`，本状态机没有运行时清故障命令。

## 6. 四框配置与逻辑位置

配置位于 `Config/project_config.h`。角度单位为有符号毫度。

| 框 | Yaw 配置 | Pitch 方向 | 当前编译默认值 | 机械状态 |
|---|---|---|---:|---|
| BOX1 | `SORT_YAW_GROUP_13_MDEG` | `SORT_BOX1_PITCH_DIRECTION` | Yaw `0L` 占位；方向 `0` | 需要实机标定 |
| BOX2 | `SORT_YAW_GROUP_24_MDEG` | `SORT_BOX2_PITCH_DIRECTION` | Yaw `0L` 占位；方向 `0` | 需要实机标定 |
| BOX3 | `SORT_YAW_GROUP_13_MDEG` | `SORT_BOX3_PITCH_DIRECTION` | Yaw `0L` 占位；方向 `0` | 需要实机标定 |
| BOX4 | `SORT_YAW_GROUP_24_MDEG` | `SORT_BOX4_PITCH_DIRECTION` | Yaw `0L` 占位；方向 `0` | 需要实机标定 |

代码强制 BOX1/BOX3 共用 Yaw 目标、Pitch 方向相反；BOX2/BOX4 共用 Yaw 目标、Pitch 方向相反。方向须配置为 `+1` 或 `-1`，并满足 `BOX1 = -BOX3`、`BOX2 = -BOX4`。倾倒幅度由 `SORT_PITCH_DUMP_ANGLE_MDEG` 配置，方向乘以该正值生成 Pitch 目标；当前幅度默认 `0L`，也是未标定占位值。

当前逻辑坐标：`SORT_YAW_HOME_MDEG = 0L`，是每次上电后人工将机构对准线缆自然走向、再在 Ozone 中设定的 Yaw 零点；没有回零传感器。`SORT_PITCH_HOME_MDEG = 0L`，对应工程现有的水平 Pitch 坐标。现有轴接口以这两个零点为坐标原点，固件会拒绝非零 HOME 配置。

在确定 `SORT_MECHANICAL_CALIBRATION_COMPLETE=1U` 前，还必须测量两个 Yaw 方位、四框 Pitch 正负方向和安全倾倒角，并确认 `YAW_AXIS_SCALE_VERIFIED=1U` 与 `SERVO_CALIBRATION_VALID=1U`。源码当前没有足够机械证据填写这些值，主机测试中的配置只用于软件测试，不代表实机参数。

Yaw 目标继续经过 `YawAxis_ValidateTargetMilliDeg()` 和现有 `-180000..+180000 mdeg` 线缆限制，不做 360° 取模或最短路绕行。

## 7. 超时、心跳和 READY

| 配置宏 | 默认值 | 用途 |
|---|---:|---|
| `SORT_YAW_STEP_FREQUENCY_HZ` | 100 PUL/s | 分拣用 Yaw 命令频率 |
| `SORT_YAW_MOVE_TIMEOUT_MS` | 30000 ms | Yaw 去目标和回 HOME 等待超时 |
| `SORT_YAW_MOVE_TIMEOUT_MARGIN_MS` | 5000 ms | 配置检查要求的额外时间裕量 |
| `SORT_PITCH_MOVE_TIMEOUT_MS` | 6000 ms | Pitch 倾倒和回 HOME 等待超时 |
| `SORT_DUMP_HOLD_MS` | 1000 ms | 倾倒保持时间 |
| `SORT_READY_HEARTBEAT_MS` | 1000 ms | 空闲 READY 周期 |

初始化时检查 Yaw timeout 覆盖最远配置目标在设定频率下的估计脉冲时长、方向建立时间和裕量；Pitch timeout 至少覆盖 Pitch 响应时间的最大配置。所有等待计时都由 Tick 非阻塞完成。

只有 `state == IDLE`、无未完成 action、无系统故障、标定配置有效、Yaw 已使能且具有有效手动零点、Yaw 回到 HOME、Pitch 回到 HOME、两轴均不忙时，`SortTask_IsReady()` 才允许发送 `R`。第一次就绪时立即发送，之后约每秒发送。默认未标定构建不满足配置有效条件，所以不会发送 `R`。

## 9. 软件验证与边界

主机测试使用仅供测试的标定宏验证四框映射、状态顺序、重复/冲突帧、BAD_BOX、BUSY、CRC 错误、倾倒保持、轴超时和未标定默认拒绝。测试宏中的角度和方向不应复制到实机配置。此次本机执行结果：主机 CTest 5/5 通过；STM32 Debug 与 Release 均完成交叉编译和链接。链接器对两个 ELF 都报告 `LOAD segment with RWX permissions` 警告。软件构建不能验证实机角度、方向、到位和线缆安全；硬件动作仍须接线和机械调试验证。

`SortTask` 和分拣状态流程不调用 `HAL_Delay()`，不通过忙等实现超时或 1 秒保持。现有 HC-04 发送沿用同步 `HAL_UART_Transmit()`，单次调用超时上限为 `HC04_TX_TIMEOUT_MS`（50 ms）；它不是分拣等待逻辑，但发生 UART TX 故障时会短暂占用主循环。Yaw 步进与 Pitch 舵机运动由现有轴任务按主循环推进。
