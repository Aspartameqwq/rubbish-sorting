# TB6600 driver interface

## Scope and evidence

`BSP/Src/tb6600.c` owns the project's PUL, DIR and ENA signals. It targets the commercial PUFEIDE-marked TB6600 module shown by the user, not a bare TB6600HG IC. The project has **selected** a 3.3 V common-cathode direct-GPIO connection. This is a design decision, not an electrical verification: input current, logic recognition, ENA behavior, DIR orientation, waveform and motor movement remain PENDING. The complete physical connection table is maintained only in [Docs/wiring.md](wiring.md).

## Pin and timer allocation

| Signal | STM32 resource | Configuration |
|---|---|---|
| PUL | TIM3_CH1 / PA6 | Hardware PWM1, no remap, selected active-high output to PUL+ |
| DIR | PB12 / `TB6600_DIR` | GPIO push-pull, selected HIGH=logical FORWARD to DIR+ |
| ENA | PB13 / `TB6600_ENA` | GPIO push-pull, selected HIGH=enable to ENA+ |

For the selected common-cathode topology, STM32 GND is connected to PUL-, DIR- and ENA-. Do not recreate a second signal connection table here; [Docs/wiring.md](wiring.md) is canonical.

TIM3 receives a 72 MHz APB1 timer clock. PSC 71 produces 1 MHz, or 1 µs/count. `TB6600Timing_Calculate()` uses integer division:

```text
period_counts = timer_tick_hz / requested_frequency_hz
ARR           = period_counts - 1
CCR           = configured pulse active width in timer counts
```

At the initial 20–10,000 PUL pulses/s range, the period is 50,000–100 counts and ARR is 49,999–99. Default pulse width is 10 counts (10 µs), so `CCR < ARR` throughout that range. The timing helper rejects zero frequency, ARR outside the 16-bit counter range, a pulse width that does not fit strictly inside the period, and invalid arguments. Timer quantization means requested and realized frequencies can differ by a fraction of a pulse/s at non-divisors.

PUL is generated by the timer peripheral. Firmware does not bit-bang PUL, toggle GPIO for step timing, or delay between pulses. PWM1 with a fixed CCR creates a fixed-width active pulse and a variable period. The final regular pulse is counted on the CH1 compare event at the end of its active width.

## Selected levels and unverified values

`Config/project_config.h` centralizes the selected signal levels and initial software values:

- `TB6600_ENABLE_ACTIVE_LEVEL = 1`: selected wiring level; PB13 HIGH drives ENA+ and LOW is the boot/inactive level. Physical ENA behavior remains PENDING.
- `TB6600_DIR_FORWARD_LEVEL = 1`: selected software convention; PB12 HIGH means logical FORWARD. Confirm actual mechanical direction during bring-up.
- `TB6600_PULSE_ACTIVE_LEVEL = 1`: selected active-high pulse level on PA6/PUL+; actual module recognition remains PENDING.
- `TB6600_PULSE_HIGH_US = 10`: initial software pulse width.
- `TB6600_STEP_FREQ_MIN_HZ = 20` and `TB6600_STEP_FREQ_MAX_HZ = 10000`: initial software PUL-frequency limits.
- `STEPPER_DIRECTION_SETUP_MS = 1`: initial nonblocking direction settling interval.

The direct common-cathode topology and DIP values are project-selected from the user plan and photographed case label. Actual signal currents, 3.3 V recognition, ENA state, DIR orientation, pulse-width margin, safe frequency and noise behavior remain PENDING. The project uses an 8 mA per-input acceptance gate before applying driver power; this is a project test criterion, not an absolute-maximum current rating. The firmware does not set driver current or microstep DIP switches.

## Motor and module-label details supplied by the user

The user reports a 1.8° step angle and approximately 1.5 A motor current, with the four motor leads connected to the module's `A+`, `A-`, `B+` and `B-` outputs. The selected switch settings follow the photographed label: S1 OFF, S2 ON, S3 OFF selects 8 microsteps / 1600 PUL pulses per revolution; S4 ON, S5 ON, S6 OFF selects the row labeled 1.5 A current and 1.7 A peak current. These are project-selected switch positions, not a measurement of motor phase current. The motor's current rating basis and coil pairing have not been independently verified; the physical DIP lever positions also need visual confirmation with power off.

The photo shows a PUFEIDE-marked `TB6600` and `DC 9–42VDC`. The project selects a 24 V DC supply for bring-up; the supply actually connected and the exact board revision are not identified. Treat the voltage range and DIP chart as printed-label information, not confirmation of the board's electrical behavior or present supply voltage.

A 1.8° motor has 200 full steps per revolution. At the selected 8 microsteps, the nominal command count is 1600 PUL pulses per motor revolution, or 0.225° per pulse, assuming direct coupling. `STEPPER MOVE` counts PUL pulses; firmware does not read or configure the module's DIP switches.

## API and ownership

`TB6600_Init()` validates the generated TIM3 instance, prescaler and starting period, configures CH1 polarity and leaves ENA inactive. `TB6600_Enable/Disable()`, `TB6600_SetDirection()`, `TB6600_SetStepFrequency()`, `TB6600_StartPulse()`, and stop/query APIs form the boundary consumed by `Motion/stepper.c`.

Only this BSP uses `htim3`, the TIM HAL calls, or the generated PB12/PB13 GPIO macros. Direction cannot change while pulse generation is active. The BSP handles completed pulse event counting; it does not interpret move distance, update position, parse a command, or know waste-sorting behavior.

## Finite pulse and interrupt behavior

The user selected CH1 pulse-finished IRQ counting. `HAL_TIM_PWM_PulseFinishedCallback()` fires on PWM1's compare event, when the active-high pulse becomes inactive. On a normal finite move, it increments the completed-pulse counter and stops PWM in the callback on exactly the requested Nth event. It also honors graceful STOP/DISABLE at the next completed pulse boundary. Main-loop `Stepper_Process()` consumes the counter and updates state/commanded position.

This terminal stop is the only low-level timer cutoff in the callback. It prevents a later update event from starting an N+1 pulse. A hard emergency stop calls the BSP from the main loop immediately; it can truncate a pulse already in progress. Since the module's pulse recognition threshold is unknown, that truncated pulse's physical interpretation cannot be guaranteed. Position accounting counts only completed compare events and remains open loop.

The highest configured frequency is 10 kHz: periods are 100 µs and the inactive gap after a 10 µs pulse is 90 µs. TIM3's compare IRQ must be serviced within that gap to stop before the next pulse edge, and each compare must be serviced within one period to avoid collapsed pending flags. Keep interrupt-disabled sections short and preserve the generated highest TIM3 IRQ priority.

## DMA reservation

No DMA backend is implemented. DMA1 Channel 3 is reserved for a future TIM3_UP → ARR-update profile stream. USART1_RX remains on DMA1 Channel 5; USART1_TX may use Channel 4 later; TIM3_CH1's DMA1 Channel 6 mapping remains unused. The current profile module is pure software and is not connected to the constant-speed pulse backend.
